## 1. 一次请求由哪几部分组成

```
POST /api/g/social/nodes?full=1&limit=20 HTTP/1.1      ← 方法 + 路径 + 查询参数
Host: 127.0.0.1:8080                                   ← 请求头
Content-Type: application/json
X-Graph: social
Content-Length: 76

{"labels":["Person"],"props":{"name":"Alice"}}          ← 请求体
```

| 组成部分        | 作用                                          | 本文章节                     |
| ----------- | ------------------------------------------- | ------------------------ |
| **方法 + 路径** | 决定调用哪个接口；路径里可带图名、资源 id                      | 第 8 章                    |
| **请求头**     | 声明体格式与长度；`X-Graph` 可指定操作哪张图                 | [第 2 章](#2-请求头headers详解) |
| **查询参数**    | `?key=value&...`，过滤、分页、方向、深度等开关             | [第 4 章](#4-通用查询参数总表)     |
| **请求体**     | JSON 对象，携带要写入的数据（POST/PUT/PATCH/DELETE 均可用） | [第 5 章](#5-通用请求体字段总表)    |

**服务支持的 HTTP 方法**：`GET` / `POST` / `PUT` / `PATCH` / `DELETE` / `OPTIONS`。  
用错方法返回 `405 method_not_allowed`。

缺省约定（下文示例统一使用）：

```bash
export B=http://127.0.0.1:8080        # 服务地址
JSON="-H Content-Type:application/json"   # 带 JSON body 时的头
```

> 若本机设置了 `HTTP_PROXY`，curl 访问 localhost 会被代理拦掉，请给每条 curl 加 `--noproxy '*'`。

## 2. 请求头（Headers）详解

### 2.1 服务端实际会读取的头

| 请求头              | 是否生效   | 说明                                                                                                   |
| ---------------- | ------ | ---------------------------------------------------------------------------------------------------- |
| `X-Graph`        | ✅ 生效   | **指定操作哪张图（数据库）**。名称大小写不敏感（`x-graph`、`X-GRAPH` 都行）。取不到则退回 `?graph=` 或默认图。见[第 3 章](#3-图路由指定操作哪张图的三种方式) |
| `Content-Length` | ✅ 生效   | HTTP 层按它收齐请求体。由 curl / 各语言 HTTP 库自动填写，**不要手填**。超过 **8 MB**（`main.cpp` 中 `8u * 1024 * 1024`）直接拒绝      |
| `Content-Type`   | ⚠️ 不校验 | 服务端不看这个头，**只要 body 非空就按 JSON 解析**。但强烈建议写 `application/json`：一是自描述，二是部分客户端/网关依赖它决定是否发送 body           |
| `Host`           | ✅ 生效   | 标准 HTTP 头，由客户端自动生成                                                                                   |
| `Accept`         | ❌ 忽略   | 服务端恒返回 `application/json`                                                                            |
| `Authorization`  | ❌ 忽略   | **本服务没有任何鉴权**，任何能访问端口的人都能读写全部数据。请勿直接暴露到公网                                                            |

### 2.2 响应里会带的头（CORS）

服务端给每个响应都加了跨域头（`main.cpp` 的 `withCors`）：

| 响应头                            | 值                                        |
| ------------------------------ | ---------------------------------------- |
| `Access-Control-Allow-Origin`  | `*`                                      |
| `Access-Control-Allow-Methods` | `GET, POST, PUT, PATCH, DELETE, OPTIONS` |
| `Access-Control-Allow-Headers` | `Content-Type`                           |

> ⚠️ **重要**：允许的请求头只有 `Content-Type`，**不含 `X-Graph`**。  
> 所以**从浏览器跨域**发请求时，`X-Graph` 会被预检拦掉；浏览器请用路径 `/api/g/{图名}/...` 或查询参数 `?graph=xxx` 来指定图。  
> `X-Graph` 只在服务端 / curl / Postman 等非浏览器场景下可靠。
>
> `OPTIONS` 预检请求直接返回 `204`，不进业务层。

### 2.3 请求头写法速查

```bash
# 无 body（GET / DELETE 常见）
curl -s "$B/api/g/social/nodes?full=1"

# 带 JSON body：必须 -H Content-Type
curl -s -X POST "$B/api/nodes" \
  -H 'Content-Type: application/json' \
  -d '{"labels":["Person"],"props":{"name":"Alice"}}'

# 用 X-Graph 头指定图（等价于 /api/g/social/... 和 ?graph=social）
curl -s "$B/api/nodes?full=1" -H 'X-Graph: social'

# 图名大小写不敏感
curl -s "$B/api/nodes" -H 'x-graph: social'
```

## 3. 图路由：指定操作哪张图的三种方式

一张图 = 一个独立 `GraphDB` = 数据目录下的一个 `<图名>.mgdb` 文件。

**优先级从高到低**：

| 优先级 | 方式                     | 示例                            |
| --- | ---------------------- | ----------------------------- |
| 1   | 路径前缀 `/api/g/{图名}/...` | `POST /api/g/social/nodes`    |
| 2   | 请求头 `X-Graph`          | `-H 'X-Graph: social'`        |
| 3   | 查询参数 `?graph=`         | `GET /api/nodes?graph=social` |
| 4   | 默认图                    | 启动参数 `--graph`（缺省 `default`）  |

三种写法完全等价：

```bash
curl -s -X POST "$B/api/g/social/nodes" -H 'Content-Type: application/json' -d '{"labels":["Person"]}'
curl -s -X POST "$B/api/nodes" -H 'X-Graph: social' -H 'Content-Type: application/json' -d '{"labels":["Person"]}'
curl -s -X POST "$B/api/nodes?graph=social" -H 'Content-Type: application/json' -d '{"labels":["Person"]}'
```

图不存在时返回 `404 graph_not_found`：

```json
{"ok":false,"error":{"code":"graph_not_found","message":"图不存在: social（GET /api/graphs 可查看全部图，POST /api/graphs 可新建）"}}
```

**旧接口路径完全不变**：`/api/nodes`、`/api/query` 等照常可用，只是内部先解析出图再分发，因此对 v1 客户端向后兼容。

图名命名规则（`validGraphName`）：

- 不能为空，长度 ≤ 64
- 只允许字母、数字、`_`、`-`、`.`、空格
- 不能是 `.` 或 `..`
- 非法返回 `400 bad_request`

## 4. 通用查询参数总表

查询参数写在 URL 的 `?` 之后，多个用 `&` 连接。

### 4.1 路由与分页

| 参数       | 类型     | 默认            | 适用于                | 说明                                                                      |
| -------- | ------ | ------------- | ------------------ | ----------------------------------------------------------------------- |
| `graph`  | string | 默认图           | 所有非 `/api/g/` 前缀接口 | 指定图名。**优先级低于**路径前缀和 `X-Graph` 头；使用 `/api/g/{name}` 时此参数被忽略              |
| `limit`  | 整数     | `100`         | 列表类、查询类            | 单页条数上限。**>1000 或 =0 时会被强制造为 1000**（上限 `kMaxLimit=1000`）。想"不分页"只能设到 1000 |
| `offset` | 整数     | `0`           | 列表类、查询类            | 跳过前 N 条，配合 `limit` 翻页                                                   |
| `full`   | bool   | 因接口而异（见第 8 章） | 列表类、遍历类            | `false` 只返回 id 数组，`true` 返回完整对象（含 labels/props）                         |

> **bool 解析规则**（`paramBool`）：值为 `""`、`0`、`false`、`no`、`False` 视为假，其余（含 `1`、`true`、`yes`、任意非空串）视为真。  
> ⚠️ 只写 `?full` 不带 `=` → 值为空串 → **判为 false**。一定要写 `?full=1` 或 `?full=true`。

### 4.2 过滤与比较（列表/查询）

| 参数      | 类型     | 默认     | 说明                                                                                                    |
| ------- | ------ | ------ | ----------------------------------------------------------------------------------------------------- |
| `label` | string | 空      | 只保留带该标签的节点                                                                                            |
| `key`   | string | 空      | 按属性键过滤。**给了 `key` 就必须同时给 `value`**，否则 `400`                                                           |
| `value` | string | 空      | 期望的属性值（文本形式，配合 `vtype` 解释）                                                                            |
| `vtype` | 枚举     | `auto` | `value` 的类型解释方式：`auto` / `int` / `double` / `bool` / `string` / `json`（见 [6.3](#63-vtype-查询参数里的类型解释)） |
| `op`    | string | `eq`   | 比较操作符，**不加 `$` 前缀**。服务端会自动补成 `$op`。可选：`eq ne gt gte lt lte in contains has size`；`eq` 表示直接相等          |

### 4.3 方向、类型、深度

| 参数          | 类型     | 默认       | 适用于                                  | 说明                                                                                                                        |
| ----------- | ------ | -------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `dir`       | 枚举     | 因接口而异    | 邻居、度数、相连关系、关系列表、可达、最短路、带权最短路         | `out`（出边）/ `in`（入边）/ `both`（双向）。**无法识别的值一律按 `out` 处理**（不报错）                                                               |
| `type`      | string | 空        | 邻居、度数、相连关系、可达、最短路、带权最短路(GET)         | 关系类型过滤，**多个用英文逗号分隔**：`type=KNOWS,WORKS_AT`。会 trim 两端空格，空段被丢弃。⚠️ **例外**：`GET /api/relationships` 的 `type` 不切分逗号，整体当一个类型名匹配 |
| `type`      | string | 空        | `GET /api/relationships`             | 只匹配单个类型名（**不支持逗号分隔**）；要按端点查请改用 `from` + `to`                                                                              |
| `types`     | 数组     | `[]`     | **仅** `POST /api/path/weighted` 的请求体 | 同上的数组形式：`"types":["KNOWS","WORKS_AT"]`                                                                                    |
| `depth`     | 整数     | `1`      | `GET /api/reachable/{id}`            | 最多走几跳                                                                                                                     |
| `weightKey` | string | `weight` | 带权最短路                                | 从关系的哪个属性上读权重；缺失或非数值的关系按权重 1 处理                                                                                            |

`dir` 默认值一览（各接口可能不同，别想当然）：

| 接口                                     | `dir` 默认                 |       |
| -------------------------------------- | ------------------------ | ----- |
| `GET /api/nodes/{id}/neighbors`        | `out`                    |       |
| `GET /api/nodes/{id}/degree`           | `both`                   |       |
| `GET /api/nodes/{id}/relationships`    | `both`                   |       |
| `GET /api/relationships`（给了 from+to 时） | `out`                    |       |
| `GET /api/reachable/{id}`              | `out`                    |       |
| `GET /api/path`                        | `out`                    |       |
| \`POST                                 | GET /api/path/weighted\` | `out` |

### 4.4 危险操作确认

| 参数        | 类型   | 适用于                                                     | 说明                                                        |
| --------- | ---- | ------------------------------------------------------- | --------------------------------------------------------- |
| `confirm` | bool | `DELETE /api/graphs/{name}`                             | 删图确认。可用 `?confirm=1` **或** 请求体 `{"confirm": true}`        |
| `confirm` | bool | `POST /api/graphs/{name}/clear`、`POST /api/admin/clear` | 清空确认。**只能用请求体 `{"confirm": true}`，query 参数无效**（实现只读 body） |

## 5. 通用请求体字段总表

请求体必须是 **JSON 对象**（传数组/标量会返回 `400 bad_json`）。只有在 body 非空时才解析，所以 GET 不带 body 完全没问题；反过来 **DELETE/PUT/PATCH 也都可以带 JSON body**。

### 5.1 写入类字段

| 字段             | 类型                      | 适用于                                                         | 说明                                                                       |
| -------------- | ----------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------ |
| `labels`       | 字符串数组（**建节点时也接受单个字符串**） | `POST /api/nodes`、`PUT /api/nodes/{id}`                     | 节点标签。POST 可写 `"Person"` 或 `["Person","User"]`；**PUT 只接受数组**，传字符串会报 `400` |
| `props`        | 对象                      | 建/改 节点与关系                                                   | 属性字典。值可为 7 种类型之一（见[第 6 章](#6-属性值类型系统)），**支持数组与对象嵌套**                     |
| `addLabels`    | 字符串数组                   | `PATCH /api/nodes/{id}`                                     | 增量加标签                                                                    |
| `removeLabels` | 字符串数组                   | `PATCH /api/nodes/{id}`                                     | 增量删标签                                                                    |
| `removeProps`  | 字符串数组                   | `PATCH /api/nodes/{id}`、`PUT/PATCH /api/relationships/{id}` | 按 key 删除属性                                                               |
| `arrayAppend`  | 对象                      | `PATCH` 节点/关系                                               | 向数组属性追加元素，**自动去重**；属性原本不存在或不是数组时，先建成空数组                                  |
| `arrayRemove`  | 对象                      | `PATCH` 节点/关系                                               | 从数组属性删除元素；属性不是数组则**静默跳过**（不报错）                                           |
| `objectMerge`  | 对象                      | `PATCH` 节点/关系                                               | 向对象属性做**浅合并**（同名键覆盖）；属性原本不存在时先建成空对象                                      |

`arrayAppend` / `arrayRemove` 的**值既可以是数组也可以是单个标量**：

```json
{"arrayAppend": {"tags": ["vip", "gold"]}}   // 追加两个
{"arrayAppend": {"score": 5}}                // 追加一个（标量自动包成单项）
```

### 5.2 查询/控制类字段

| 字段                 | 类型       | 适用于                       | 说明                                |
| ------------------ | -------- | ------------------------- | --------------------------------- |
| `name` / `graph`   | string   | `POST /api/graphs`        | 新图名，二者取其一（`name` 优先）              |
| `confirm`          | bool     | 删图 / 清空图                  | 危险操作确认                            |
| `label`            | string   | `POST /api/query`、建索引、删索引 | 标签名                               |
| `where`            | 对象       | `POST /api/query`         | 查询条件，见[第 7 章](#7-查询操作符-where)     |
| `limit` / `offset` | 整数       | `POST /api/query`         | 同查询参数版；`limit ≤ 0 或 >1000` → 1000 |
| `full`             | bool     | `POST /api/query`         | 是否返回完整对象                          |
| `key`              | string   | 建/删索引                     | 被索引的属性键                           |
| `from` / `to`      | 整数或数字字符串 | 建关系、带权最短路                 | 端点节点 id。数字字符串（如 `"12"`）也接受        |
| `type`             | string   | 建关系、改关系                   | 关系类型，建关系时**必填且非空**                |
| `types`            | 字符串数组    | `POST /api/path/weighted` | 关系类型白名单                           |
| `weightKey`        | string   | `POST /api/path/weighted` | 权重属性键，默认 `weight`                 |
| `dir`              | 枚举       | `POST /api/path/weighted` | 默认 `out`                          |

## 6. 属性值系统

### 6.1 支持的 7 种类型

| JSON 写法                                            | 内部类型   | 落盘标记 | 说明                          |
| -------------------------------------------------- | ------ | ---- | --------------------------- |
| `null`                                             | Null   | `0`  | 空值                          |
| `-9223372036854775808` ~ `9223372036854775807` 的整数 | Int    | `1`  | 64 位有符号整数                   |
| `3.14`、`1e5`                                       | Double | `2`  | 双精度浮点                       |
| `true` / `false`                                   | Bool   | `3`  | 布尔                          |
| `"Alice"`                                          | String | `4`  | UTF-8 字符串                   |
| `["vip", "gold"]`                                  | Array  | `5`  | **数组**，元素可为任意 7 型，可嵌套       |
| `{"city":"Beijing"}`                               | Object | `6`  | **对象**（键有序字典），值可为任意 7 型，可嵌套 |

数组与对象可任意嵌套，例如：

```json
{
  "name": "Alice",
  "tags": ["vip", "early-bird"],
  "addr": {"city": "Beijing", "zip": "100000"},
  "matrix": [[1, 2], [3, 4]],
  "profile": {"skills": ["C++", "Go"], "boss": {"name": "Bob"}}
}
```

**限制**：嵌套深度上限 **32 层**（JSON 解析侧），超过返回 `400`。

### 6.2 相等性判定（`$eq` / 默认比较）

| 情形                           | 是否相等                     |
| ---------------------------- | ------------------------ |
| `30` vs `30.0`               | ✅ 相等（数值间跨 int/double 比较） |
| `30` vs `"30"`               | ❌ 不相等（不做跨类型隐式转换）         |
| `[1,2]` vs `[1,2]`           | ✅ 长度相同且逐项相等（递归同一套规则）     |
| `{"a":1}` vs `{"a":1.0}`     | ✅ 键集合相同且每键值相等            |
| `{"a":1,"b":2}` vs `{"a":1}` | ❌ 键数不同                   |

### 6.3 `vtype`：查询参数里的类型解释

用 query string 过滤时，`value` 只是文本，需要 `vtype` 告诉服务端怎么解释：

| `vtype`    | 行为                                | 示例                                                                                 |
| ---------- | --------------------------------- | ---------------------------------------------------------------------------------- |
| `auto`（默认） | 依次尝试：整数 → 浮点 → `true/false` → 字符串 | `value=30` → Int 30；`value=30.5` → Double；`value=true` → Bool；`value=abc` → String |
| `int`      | 强制整数，非整数返回 `400`                  | `value=30&vtype=int`                                                               |
| `double`   | 强制浮点                              | `value=30.5&vtype=double`                                                          |
| `bool`     | 只接受 `true/1/false/0`              | `value=1&vtype=bool` → true                                                        |
| `string`   | 一律当字符串（**想按字符串比较数字时必用**）          | `value=30&vtype=string` → "30"                                                     |
| `json`     | 按 JSON 解析，可传数组/对象                 | `value=["vip"]&vtype=json`（记得 URL 编码）                                              |

```bash
# 按字符串比较：找出 zip 为 "100000" 的节点（而不是数字 100000）
curl -s "$B/api/nodes?key=zip&value=100000&vtype=string&full=1"

# 按数组比较：tags 恰好等于 ["vip"]
curl -s --get "$B/api/nodes" --data-urlencode 'key=tags' \
     --data-urlencode 'value=["vip"]' --data-urlencode 'vtype=json' --data-urlencode 'full=1'
```


## 8. 逐接口参数详解

> 每个接口给出：方法路径 → 参数表（**位置**列标明 P=路径参数、Q=查询参数、H=请求头、B=请求体）→ curl 示例。  
> 示例中的 `/api/g/social/...` 均可替换为 `-H 'X-Graph: social'` 或 `?graph=social`（见[第 3 章](#3-图路由指定操作哪张图的三种方式)）。

### 8.1 健康检查与自描述

#### ① `GET /api/health` —— 健康检查

无参数。返回服务状态、数据目录、默认图、全部图名与总量。

| 参数 | 位置 | 必填 | 说明 |
| -- | -- | -- | -- |
| —  | —  | —  | 无  |

```bash
curl -s "$B/api/health"
```

#### ② `GET /api/manifest` —— 接口清单

无参数。返回版本号、图路由说明与全部接口列表（自描述）。

```bash
curl -s "$B/api/manifest" | python3 -m json.tool
```

### 8.2 图（数据库）管理

#### ③ `GET /api/graphs` —— 列出所有图

无参数。返回 `dataDir`、`defaultGraph`、`total` 与 `items[]`（每张图的 name / file / fileSize / nodes / relationships / isDefault）。

```bash
curl -s "$B/api/graphs"
```

#### ④ `POST /api/graphs` —— 新建图

| 参数      | 位置 | 类型     | 必填           | 默认 | 说明                          |
| ------- | -- | ------ | ------------ | -- | --------------------------- |
| `name`  | B  | string | 是（或 `graph`） | —  | 图名。`name` 为空时回退读 `graph` 字段 |

### 8.3 节点

#### ⑨ `POST /api/nodes` —— 创建节点

| 参数       | 位置 | 类型              | 必填 | 默认   | 说明                               |
| -------- | -- | --------------- | -- | ---- | -------------------------------- |
| `labels` | B  | 字符串 **或** 字符串数组 | 否  | `[]` | 标签。`"Person"` 与 `["Person"]` 都接受 |
| `props`  | B  | 对象              | 否  | `{}` | 属性，**值可为数组/对象**                  |

成功返回 `201`，`data.id` 是新节点 id，`data.node` 是完整对象。

```bash
curl -s -X POST "$B/api/g/social/nodes" \
  -H 'Content-Type: application/json' \
  -d '{
        "labels": ["Person"],
        "props": {
          "name": "Alice",
          "age": 30,
          "tags": ["vip", "early-bird"],
          "addr": {"city": "Beijing", "zip": "100000"}
        }
      }'
```

#### ⑩ `GET /api/nodes` —— 列出/过滤节点

| 参数       | 位置 | 类型     | 默认      | 说明                                                 |
| -------- | -- | ------ | ------- | -------------------------------------------------- |
| `label`  | Q  | string | 空       | 按标签过滤                                              |
| `key`    | Q  | string | 空       | 属性键；给了 `key` 必须给 `value`                           |
| `value`  | Q  | string | 空       | 期望值（文本）                                            |
| `vtype`  | Q  | 枚举     | `auto`  | `auto/int/double/bool/string/json`                 |
| `op`     | Q  | string | `eq`    | `eq ne gt gte lt lte in contains has size`（不加 `$`） |
| `limit`  | Q  | 整数     | `100`   | `0` 或 `>1000` → 1000                               |
| `offset` | Q  | 整数     | `0`     | 跳过条数                                               |
| `full`   | Q  | bool   | `false` | `1` 返回完整节点，`0` 只返回 id 数组                           |

```bash
# 列全部（只要 id）
curl -s "$B/api/g/social/nodes"

# 带标签 + 完整对象 + 分页
curl -s "$B/api/g/social/nodes?label=Person&full=1&limit=20&offset=0"

# 单条件过滤（走索引最快）
curl -s "$B/api/g/social/nodes?label=Person&key=name&value=Alice&full=1"

# 数组包含
curl -s "$B/api/g/social/nodes?key=tags&value=vip&op=contains&full=1"
```

#### ⑪ `GET /api/nodes/{id}` —— 查询单个节点

| 参数   | 位置 | 类型 | 必填 | 说明                            |
| ---- | -- | -- | -- | ----------------------------- |
| `id` | P  | 整数 | 是  | 节点 id，非数字返回 `400`；不存在返回 `404` |

```bash
curl -s "$B/api/g/social/nodes/1"
```

#### ⑫ `PUT /api/nodes/{id}` —— 整体替换

| 参数       | 位置 | 类型        | 必填 | 说明                                                                  |
| -------- | -- | --------- | -- | ------------------------------------------------------------------- |
| `id`     | P  | 整数        | 是  | 节点 id                                                               |
| `labels` | B  | **字符串数组** | 否  | ⚠️ 只接受数组（与 POST 不同）。给出的即为最终标签集：不在列表里的旧标签会被删除，列表里没有的会被添加。省略则**标签不变** |
| `props`  | B  | 对象        | 否  | **整体替换**属性：先清空全部旧属性再写入。省略则属性不变                                      |

```bash
curl -s -X PUT "$B/api/g/social/nodes/1" \
  -H 'Content-Type: application/json' \
  -d '{"labels":["Person","Manager"],"props":{"name":"Alice","age":31}}'
```

#### ⑬ `PATCH /api/nodes/{id}` —— 增量修改

| 参数             | 位置 | 类型    | 默认 | 说明                    |
| -------------- | -- | ----- | -- | --------------------- |
| `id`           | P  | 整数    | —  | 节点 id                 |
| `addLabels`    | B  | 字符串数组 | —  | 加标签                   |
| `removeLabels` | B  | 字符串数组 | —  | 删标签                   |
| `props`        | B  | 对象    | —  | **合并**属性：只覆盖写到的键，其余保留 |
| `removeProps`  | B  | 字符串数组 | —  | 按 key 删除属性            |
| `arrayAppend`  | B  | 对象    | —  | 数组追加（去重）；值可为数组或标量     |
| `arrayRemove`  | B  | 对象    | —  | 数组删元素；属性不是数组则跳过       |
| `objectMerge`  | B  | 对象    | —  | 对象浅合并                 |

**执行顺序**：`addLabels` → `removeLabels` → `props` → `removeProps` → `arrayAppend` → `arrayRemove` → `objectMerge`。

```bash
# 改属性 + 加标签
curl -s -X PATCH "$B/api/g/social/nodes/1" \
  -H 'Content-Type: application/json' \
  -d '{"props":{"age":31},"addLabels":["Manager"],"removeProps":["nickname"]}'

# 数组追加（自动去重）
curl -s -X PATCH "$B/api/g/social/nodes/1" \
  -H 'Content-Type: application/json' \
  -d '{"arrayAppend":{"tags":["gold","vip"]}}'

# 数组删元素
curl -s -X PATCH "$B/api/g/social/nodes/1" \
  -H 'Content-Type: application/json' \
  -d '{"arrayRemove":{"tags":["vip"]}}'

# 对象合并
curl -s -X PATCH "$B/api/g/social/nodes/1" \
  -H 'Content-Type: application/json' \
  -d '{"objectMerge":{"addr":{"street":"长安街","city":"上海"}}}'
```

#### ⑭ `DELETE /api/nodes/{id}` —— 删除节点

| 参数   | 位置 | 类型 | 必填 | 说明    |
| ---- | -- | -- | -- | ----- |


| `type` | Q  | string            | 空       | 关系类型，逗号分隔  |
| `full` | Q  | bool              | `false` | `1` 返回完整节点 |

```bash
curl -s "$B/api/g/social/nodes/1/neighbors?dir=both&full=1"
```

| 参数     | 位置 | 类型     | 默认         | 说明        |
| ------ | -- | ------ | ---------- | --------- |
| `id`   | P  | 整数     | —          | 节点 id     |
| `dir`  | Q  | 枚举     | **`both`** | 注意默认是双向   |
| `type` | Q  | string | 空          | 关系类型，逗号分隔 |

#### ⑰ `GET /api/nodes/{id}/relationships` —— 相连的关系

| 参数     | 位置 | 类型     | 默认         | 说明                                     |
| ------ | -- | ------ | ---------- | -------------------------------------- |
| `id`   | P  | 整数     | —          | 节点 id                                  |
| `dir`  | Q  | 枚举     | **`both`** | 方向                                     |
| `type` | Q  | string | 空          | 关系类型，逗号分隔                              |

### 8.4 关系

#### ⑱ `POST /api/relationships` —— 创建关系

| ------- | -- | -------- | ----- | --------------------- |
| `from`  | B  | 整数或数字字符串 | **是** | 起点节点 id。节点不存在 → `404` |
| `to`    | B  | 整数或数字字符串 | **是** | 终点节点 id。节点不存在 → `404` |
| `type`  | B  | string   | **是** | 关系类型，必须非空字符串          |
| `props` | B  | 对象       | 否     | 属性，同样支持数组/对象          |

```bash
curl -s -X POST "$B/api/g/social/relationships" \
```

#### ⑲ `GET /api/relationships` —— 列出关系

| 参数       | 位置 | 类型     | 默认      | 说明                            |
| -------- | -- | ------ | ------- | ----------------------------- |
| `type`   | Q  | string | 空       | 按类型过滤（单值，非逗号列表；本接口直接当整体字符串匹配） |
| `from`   | Q  | 整数     | 空       | 起点 id。**与 `to` 同时给出**时按端点查    |
| `to`     | Q  | 整数     | 空       | 终点 id                         |
| `dir`    | Q  | 枚举     | `out`   | 仅在 `from`+`to` 都给出时生效         |
| `limit`  | Q  | 整数     | `100`   | 上限 1000                       |
| `offset` | Q  | 整数     | `0`     | 跳过条数                          |
| `full`   | Q  | bool   | `false` | `1` 返回完整关系                    |

### 8.5 查询 / 遍历 / 算法

#### ㉔ `POST /api/query` —— 条件查询（推荐）

| 参数       | 位置 | 类型     | 默认      | 说明                                          |
| -------- | -- | ------ | ------- | ------------------------------------------- |
| `label`  | B  | string | `""`    | 标签过滤。空串 = 不限                                |
| `where`  | B  | 对象     | 空       | 查询条件，见[第 7 章](#7-查询操作符-where)。传 `null` 表示忽略 |
| `limit`  | B  | 整数     | `100`   | `≤0` 或 `>1000` → 1000                       |
| `offset` | B  | 整数     | `0`     | 跳过条数                                        |
| `full`   | B  | bool   | `false` | `true` 返回完整节点                               |

```bash
curl -s -X POST "$B/api/g/social/query" \
  -H 'Content-Type: application/json' \
  -d '{"label":"Person","where":{"age":{"$gte":30},"tags":{"$contains":"vip"}},"limit":20,"full":true}'
```

#### ㉕ `GET /api/query` —— 条件查询（query string 版）

服务端内部把参数组装成与 ㉔ 等价的请求体。

| 参数       | 位置 | 类型     | 默认      | 说明                                 |
| -------- | -- | ------ | ------- | ---------------------------------- |
| `label`  | Q  | string | 空       | 标签                                 |
| `key`    | Q  | string | 空       | 属性键                                |
| `value`  | Q  | string | 空       | 期望值                                |
| `vtype`  | Q  | 枚举     | `auto`  | 类型解释                               |
| `op`     | Q  | string | `eq`    | 操作符，**不加 `$`**；非 `eq` 时服务端拼成 `$op` |
| `limit`  | Q  | 整数     | `100`   | 上限 1000                            |
| `offset` | Q  | 整数     | `0`     | 跳过条数                               |
| `full`   | Q  | bool   | `false` | 完整对象                               |

⚠️ 只支持**单个**条件（一个 `key`），多条件请用 ㉔。

```bash
curl -s "$B/api/g/social/query?label=Person&key=age&value=30&op=gte&full=1"
curl -s "$B/api/g/social/query?key=tags&value=vip&op=contains&full=1"
curl -s "$B/api/g/social/query?label=Person&key=name&value=Alice&op=eq&full=1"
```

#### ㉖ `GET /api/reachable/{id}` —— N 跳内可达节点

| ------ | -- | ------ | ------ | ------------------- |
| `from` | Q  | 整数     | **必填** | 起点 id，缺失/非法 → `400` |
| `to`   | Q  | 整数     | **必填** | 终点 id               |
| `dir`  | Q  | 枚举     | `out`  | 方向                  |
| `type` | Q  | string | 空      | 关系类型，逗号分隔           |

返回 `found`、`hops`（跳数，`-1` 表示不通）、`nodes`（路径上的节点 id 序列）。

| 参数          | 位置 | 类型        | 默认       | 说明                                    |

| `to`        | B  | 整数或数字字符串  | **必填**   | 终点 id                                 |
| `weightKey` | B  | string    | `weight` | 从关系的哪个属性读权重                           |
| `dir`       | B  | 枚举        | `out`    | 方向                                    |

返回 `found`、`cost`、`weightKey`、`nodes`、`relationships`。

```bash
curl -s -X POST "$B/api/g/social/path/weighted" \
```

#### ㉛ `POST /api/indexes` —— 创建索引

| 参数      | 位置 | 类型     | 必填    | 说明  |
| ------- | -- | ------ | ----- | --- |
| `label` | B  | string | **是** | 标签名 |
| `key`   | B  | string | **是** | 属性键 |

两个都必须是字符串，否则 `400`。返回 `201`。索引只对**标量值**生效，容器值不进索引。

```bash
curl -s -X POST "$B/api/g/social/indexes" \
  -H 'Content-Type: application/json' -d '{"label":"Person","key":"name"}'
```

#### ㉜ `DELETE /api/indexes` —— 删除索引

| 参数      | 位置        | 类型     | 必填    | 说明                       |
| ------- | --------- | ------ | ----- | ------------------------ |
| `label` | Q **或** B | string | **是** | 标签名；query 优先，为空时回退读 body |
| `key`   | Q **或** B | string | **是** | 属性键；同上                   |

```bash
curl -s -X DELETE "$B/api/g/social/indexes?label=Person&key=name"
# 或
curl -s -X DELETE "$B/api/g/social/indexes" \
  -H 'Content-Type: application/json' -d '{"label":"Person","key":"name"}'
```

### 8.7 运维

#### ㉝ `GET /api/stats` —— 当前图统计

无参数。返回节点数、关系数、标签分布、关系类型分布、索引列表。

```bash
curl -s "$B/api/g/social/stats"
```

#### ㉞ `POST /api/admin/save` —— 全部图落盘

无参数。遍历所有图逐个 `save()`；任一失败返回 `500` 并在 `data.failed` 里列出图名。

```bash
curl -s -X POST "$B/api/admin/save"
```

#### ㉟ `POST /api/admin/clear` —— 清空当前图

| 参数        | 位置      | 类型   | 必填    | 说明                                            |
| --------- | ------- | ---- | ----- | --------------------------------------------- |
| `confirm` | **仅 B** | bool | **是** | ⚠️ 只能写 `{"confirm":true}`，`?confirm=1` **无效** |

"当前图"由图路由决定（路径 / 头 / `?graph=`）。

```bash
curl -s -X POST "$B/api/admin/clear" \
  -H 'Content-Type: application/json' -d '{"confirm":true}'
```

#### ㊱ 控制台页面 `GET /`

无参数，返回 HTML 控制台（可视化发请求、带图选择器）。

```bash
# 浏览器打开 http://127.0.0.1:8080/
```

## 9. 响应结构与错误码

### 9.1 统一响应格式

成功：

```json
{
  "ok": true,
  "data": { "...": "..." }
}
```

失败：

```json
{
  "ok": false,
  "error": {
    "code": "not_found",
    "message": "节点不存在: 999"
  }
}
```

列表类接口 `data` 的通用形状：

```json
{"total": 42, "offset": 0, "limit": 100, "items": [ ... ]}
```

### 9.2 错误码

| HTTP | `code`               | 含义                                                | 处理建议                  |
| ---- | -------------------- | ------------------------------------------------- | --------------------- |
| 400  | `bad_json`           | 请求体不是合法 JSON，或不是 JSON 对象                          | 检查转义与括号               |
| 400  | `bad_request`        | 参数缺失/非法（缺 `type`、缺 `confirm`、`labels` 格式错、id 非法等） | 看 `message`           |
| 404  | `not_found`          | 节点/关系/路径不存在                                       | 确认 id                 |
| 404  | `graph_not_found`    | 图不存在                                              | `GET /api/graphs` 查名字 |
| 405  | `method_not_allowed` | 方法用错                                              | 见第 8 章各接口的方法          |
| 409  | `already_exists`     | 图已存在                                              | 换名字或直接复用              |
| 500  | `internal_error`     | 落盘失败、创建失败等                                        | 看服务端日志                |

## 10. 易踩的坑

| #  | 坑                                              | 正确写法                                                                                                         |
| -- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 1  | `?full` 不带值 → 空串 → 判为 **false**                | `?full=1` / `?full=true`                                                                                     |
| 2  | `limit=0` 本想"不分页"，实际被改成 **1000**               | 显式写 `limit=1000`                                                                                             |
| 3  | `PUT /nodes/{id}` 的 `labels` 传字符串              | PUT 只接受**数组**（POST 才允许字符串）                                                                                   |
| 4  | `POST /graphs/{name}/clear` 用 `?confirm=1`     | 清空类接口**只读 body**，必须 `-d '{"confirm":true}'`                                                                  |
| 5  | 浏览器跨域发 `X-Graph` 被拦                            | CORS 只放行 `Content-Type`；浏览器改用 `/api/g/{name}/...` 或 `?graph=`                                                |
| 6  | 数字属性按字符串查不到                                    | 加 `vtype=string`（或反过来 `vtype=int`）                                                                           |
| 7  | 数组/对象查询很慢                                      | 容器不进索引，必然全表扫描；热查询请改用标量属性 + 索引                                                                                |
| 8  | `{"addr":{"city":"北京"}}` 被当成整体相等               | 要判断"含某键"请用 `$has`，要判断"含某值"用 `$contains`                                                                      |
| 9  | `dir=OUTSIDE` 之类的错值                            | 静默按 `out` 处理，不报错                                                                                             |
| 10 | 按 `data.items` 取遍历结果                           | 只有列表类（`/nodes`、`/relationships`、`/query`）用 `items`；邻居/相连关系/可达/最短路分别用 `neighbors` / `relationships` / `nodes` |
| 11 | `GET /api/relationships?type=KNOWS,LIKES` 想查两种 | 该接口的 `type` **不按逗号切分**，整体当单个类型名匹配，结果 0 条。要查两端点之间多类型请用 `?from=&to=&dir=&type=` 逐次，或先拉全量再过滤                    |
| 12 | 改关系 `type` 后 id 变了                             | 实现是删除+重建；用响应里的 `id` 与 `idChanged`                                                                            |
| 13 | `no` / `False` 被当假，但 `No` / `FALSE` 被当真        | bool 只认 `""`、`0`、`false`、`no`、`False` 为假                                                                     |
| 14 | 删节点后关系 404                                     | 删节点会**级联删除**其所有关系                                                                                            |
| 15 | 请求体超 8 MB                                      | 服务端上限 `8 MB`，更大的图请拆分写入                                                                                       |
| 16 | 本机有 HTTP 代理时 curl 报 502                        | 每条 curl 加 `--noproxy '*'`                                                                                    |
| 17 | 分块传输                                           | 不支持 `Transfer-Encoding: chunked`，必须带 `Content-Length`                                                        |
| 18 | 并发写                                            | 服务端全局单锁串行处理；高并发请自行排队或改批量                                                                                     |

## 附：端到端示例脚本

```bash
export B=http://127.0.0.1:8080
G=/api/g/social            # 路径前缀方式指定图

# 1. 建图
curl -s -X POST "$B/api/graphs" -H 'Content-Type: application/json' -d '{"name":"social"}'

# 2. 建两个节点（带数组 / 对象属性）
curl -s -X POST "$B$G/nodes" -H 'Content-Type: application/json' -d \
  '{"labels":["Person"],"props":{"name":"Alice","age":30,"tags":["vip"],"addr":{"city":"Beijing"}}}'
curl -s -X POST "$B$G/nodes" -H 'Content-Type: application/json' -d \
  '{"labels":["Person"],"props":{"name":"Bob","age":26,"tags":["new"]}}'

# 3. 建关系
curl -s -X POST "$B$G/relationships" -H 'Content-Type: application/json' -d \
  '{"from":1,"to":2,"type":"KNOWS","props":{"since":2019,"weight":3}}'

# 4. 建索引 + 条件查询
curl -s -X POST "$B$G/indexes" -H 'Content-Type: application/json' -d '{"label":"Person","key":"name"}'
curl -s -X POST "$B$G/query" -H 'Content-Type: application/json' -d \
  '{"label":"Person","where":{"age":{"$gte":28}},"full":true}'

# 5. 数组 / 对象增量操作
curl -s -X PATCH "$B$G/nodes/1" -H 'Content-Type: application/json' -d '{"arrayAppend":{"tags":["gold"]}}'
curl -s -X PATCH "$B$G/nodes/1" -H 'Content-Type: application/json' -d '{"objectMerge":{"addr":{"street":"长安街"}}}'

# 6. 遍历与算法
curl -s "$B$G/nodes/1/neighbors?dir=both&full=1"
curl -s "$B$G/reachable/1?depth=2&dir=out"
curl -s "$B$G/path?from=1&to=2"
curl -s -X POST "$B$G/path/weighted" -H 'Content-Type: application/json' -d '{"from":1,"to":2,"weightKey":"weight"}'

# 7. 落盘（两种粒度）
curl -s -X POST "$B/api/graphs/social/save"   # 只落盘这一张图
curl -s -X POST "$B/api/admin/save"           # 全部图一起落盘

# 8. 清理
curl -s -X DELETE "$B$G/nodes/2"                       # 删节点（会级联删关系）
curl -s -X POST "$B/api/graphs/social/clear" -H 'Content-Type: application/json' -d '{"confirm":true}'
curl -s -X DELETE "$B/api/graphs/social?confirm=1"     # 连图一起删
```
